Advanced features

Past raw HTTP calls.

The resource methods cover every endpoint, but a few things needed more than a flat method signature. This page covers all of them.

Pagination

Nomba's list endpoints are cursor-paginated server-side — they return a cursor you feed back in for the next page. paginate (sync) and apaginate (async) drive that loop for you with an iterator; no second pagination scheme is introduced. 

use nomba::{Nomba, paginate};

let nomba = Nomba::new("id", "secret", "account_id")?;

for account in paginate(|| nomba.accounts.list_all_accounts()) {
    println!("{}", account.account_ref);
}

Async variant:

use nomba::{AsyncNomba, apaginate};

let nomba = AsyncNomba::new("id", "secret", "account_id").await?;

for await account in apaginate(|| nomba.accounts.list_all_accounts()) {
    println!("{}", account.account_ref);
}

Confirmed paginated endpoints: accounts.list_all_accounts, accounts.fetch_terminals_assigned_to_account, accounts.fetch_terminals_assigned_to_parent_account, virtual_accounts.filter_virtual_accounts, and all six transactions.* list/filter methods.

Guided card-payment flow

Card checkout is a multi-step sequence: submit card details, then maybe an OTP, maybe a 3D Secure redirect, then confirm. CardPaymentFlow (sync) and AsyncCardPaymentFlow (async) wrap the sequence and decode Nomba's response codes into plain booleans, instead of you needing to know what "T0" or "S0" mean. 

use nomba::{Nomba, CardPaymentFlow, CardPaymentStep};

let nomba = Nomba::new("id", "secret", "account_id")?;

let order = nomba.checkout.create_order(
    "order-001", "1000", "NGN",
    "jane@example.com", "Jane Doe",
    "https://example.com/callback", None, None
)?;

let mut flow = CardPaymentFlow::new(nomba, order.data.order_reference);
let mut step = flow.submit_card("encrypted_card_details", "rsa_key")?;

if step.requires_otp {
    step = flow.submit_otp("123456")?;
} else if step.requires_3ds {
    // redirect the user using step.secure_authentication_data
}

if step.completed {
    let result = flow.confirm()?;
}

Async variant with AsyncCardPaymentFlow:

use nomba::{AsyncNomba, AsyncCardPaymentFlow};

let nomba = AsyncNomba::new("id", "secret", "account_id").await?;

let order = nomba.checkout.create_order(
    "order-001", "1000", "NGN",
    "jane@example.com", "Jane Doe",
    "https://example.com/callback", None, None
).await?;

let mut flow = AsyncCardPaymentFlow::new(nomba, order.data.order_reference);
let mut step = flow.submit_card("encrypted_card_details", "rsa_key").await?;

if step.requires_otp {
    step = flow.submit_otp("123456").await?;
} else if step.requires_3ds {
    // redirect the user using step.secure_authentication_data
}

if step.completed {
    let result = flow.confirm().await?;
}

step is a CardPaymentStep with .completed, .requires_otp, .requires_3ds, .transaction_id, .message.

Webhook signature verification

Implements Nomba's documented HMAC-SHA256 scheme (nomba-signature / nomba-timestamp headers, base64-encoded signature) plus a replay-window check on the timestamp — a valid signature alone doesn't prove a webhook wasn't captured and resent later. 

use nomba::{verify_webhook_signature, check_timestamp_freshness, NombaError};

fn handle_webhook(body: &str, headers: &std::collections::HashMap) -> Result<(), NombaError> {
    let signature = headers.get("nomba-signature").ok_or(NombaError::Auth("Missing signature".into()))?;
    let timestamp = headers.get("nomba-timestamp").ok_or(NombaError::Auth("Missing timestamp".into()))?;

    // Verify signature
    let payload = verify_webhook_signature("your-signature-key", body, signature)?;

    // Check replay window (5 min default)
    check_timestamp_freshness(timestamp, Some(300))?;

    // Process the payload
    if payload.event_type == "payment_success" {
        // ...
    }
    Ok(())
}

Pass max_age_seconds: None to check_timestamp_freshness to disable the replay check if you have your own.

Local request validation

With the validation feature enabled, every write call (POST/PUT) is validated against Nomba's bundled OpenAPI spec before any network call. This catches missing required fields in nested request bodies that Rust's type system can't enforce. 

use nomba::{validate_body, NombaError};
use serde_json::json;

let body = json!({
    "orderReference": "order-001",
    "customerId": "cust-001",
    "callbackUrl": "https://example.com/cb",
    "customerEmail": "jane@example.com",
    "amount": 1000,
    "currency": "NGN",
    "allowedPaymentMethods": ["CARD", "ACCOUNT_TRANSFER"],
});

match validate_body("post", "/v1/checkout/orders", &body) {
    Ok(_) => println!("Request is valid"),
    Err(NombaError::Validation { missing, .. }) => {
        eprintln!("Missing fields: {:?}", missing);
    }
    Err(e) => eprintln!("Error: {}", e),
}

Reliability: locking + retry/backoff

The HTTP client guards token fetching with a lock, so concurrent requests never race to re-fetch a token — only one fetch happens, the rest reuse it. Requests that hit a 429 or transient 5xx retry automatically with exponential backoff, respecting Retry-After when Nomba sends one. 

use nomba::{NombaClientConfig, Nomba};

let config = NombaClientConfig::new("id".into(), "secret".into(), "account_id".into())
    .max_retries(3)           // default
    .retry_delay_ms(1000);    // default; delay ~= retry_delay * 2^attempt

let nomba = Nomba::from_config(config)?;

Bounded concurrency for fan-out calls

Firing off many calls at once can trigger a retry storm if several start failing together, or just trip Nomba's rate limit by bursting too many requests in one window. gather_limited (sync) and gather_limited_async (async) run the same calls with a cap. 

use nomba::{Nomba, gather_limited};

let nomba = Nomba::new("id", "secret", "account_id")?;

let refs = vec!["acct-1", "acct-2", "acct-3", "acct-4", "acct-5"];
let calls: Vec<_> = refs.into_iter().map(|r| move || nomba.virtual_accounts.fetch_virtual_account(r)).collect();

let results = gather_limited(calls, 5)?; // limit 5 concurrent
for r in results {
    match r {
        Ok(acc) => println!("{}", acc.data.account_ref),
        Err(e) => eprintln!("Error: {}", e),
    }
}

Async variant with gather_limited_async:

use nomba::{AsyncNomba, gather_limited_async};

let nomba = AsyncNomba::new("id", "secret", "account_id").await?;

let refs = vec!["acct-1", "acct-2", "acct-3", "acct-4", "acct-5"];
let calls: Vec<_> = refs.into_iter().map(|r| {
    let nomba = nomba.clone();
    async move { nomba.virtual_accounts.fetch_virtual_account(r).await }
}).collect();

let results = gather_limited_async(calls, 5).await;
for r in results {
    match r {
        Ok(acc) => println!("{}", acc.data.account_ref),
        Err(e) => eprintln!("Error: {}", e),
    }
}
